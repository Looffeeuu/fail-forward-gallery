# Fail Forward Gallery V0.2：账户与匿名身份基础

V0.2 开始把静态原型迁移为可连接正式服务的产品。第一阶段只建立账户边界、登录界面和“我的故事”信息架构，不使用浏览器本地存储伪造登录，也不宣称邮件验证码已经可用。

## 本阶段已经开始的内容

- 新增邮箱登录和验证码界面，未接入服务时明确说明不会发送或保存信息。
- 新增 `auth.js`，定义可替换的认证适配器、会话状态和权限判断。
- 将私密账户身份与公开匿名身份分开。
- 新增“我的故事”工作区入口，预留投稿、审核、Follow-up、申诉和撤回状态。
- 保持纯 HTML、CSS 和原生 JavaScript；暂不绑定具体云厂商。

## 下一步接入顺序

1. 确认部署地区、数据驻留要求和认证服务供应商。
2. 实现服务端邮箱验证码、HttpOnly 会话 Cookie、限流与审计。
3. 将投稿和评论改为必须登录后通过 API 创建。
4. 实现只返回当前账户内容的“我的故事”接口。
5. 接入人工审核后台后，才开放正式发布能力。

## 当前限制

`auth.js` 默认处于 `unconfigured` 状态。点击登录按钮只会得到明确提示，不会发起网络请求。正式适配器必须实现 `restoreSession`、`requestEmailCode`、`verifyEmailCode` 和 `signOut` 四个方法。
