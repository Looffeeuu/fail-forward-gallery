# V0.2 认证契约

## 身份边界

- `account_id` 是服务端私有标识，不得进入公开故事、评论或 Follow-up 响应。
- 公开内容只返回匿名作者类型，例如 `anonymous-member`。
- 邮箱只用于验证、找回和状态通知，不作为公开昵称，也不进入全文审核提示词。
- 管理员界面默认不展示邮箱；只有具备明确权限和审计记录的操作才能查看必要身份信息。

## 客户端适配器

正式认证实现需要向 `window.FFG_AUTH.configure(adapter)` 提供：

```js
{
  restoreSession(),
  requestEmailCode(email),
  verifyEmailCode({ email, code }),
  signOut()
}
```

适配器返回的账户对象只应包含客户端授权所需的最少字段。浏览器端不保存长期令牌；正式会话建议由服务端通过 `Secure`、`HttpOnly`、`SameSite` Cookie 管理。

当前 `auth-http-adapter.js` 已实现该契约，接口细节见 [auth-api.yaml](./auth-api.yaml)。前端运行配置只包含公开值，禁止放置邮件服务密钥、数据库凭据或签名密钥。

## 最低安全要求

- 邮箱验证码有短有效期、单次使用、尝试次数和发送频率限制。
- 请求验证码时始终返回模糊结果，避免泄露邮箱是否注册。
- 登录、退出、验证码失败和敏感账户操作写入安全审计日志。
- 修改邮箱、导出数据和删除账户前需要重新验证。
- 投稿、评论和 Follow-up 的所有权由服务端根据会话确定，客户端传入的账户 ID 不可信。
- 不在日志、分析事件或错误追踪中记录验证码、完整邮箱和故事正文。

## 待确认决策

- 中国用户的部署地区、跨境数据与隐私合规方案。
- 邮件服务商、发件域名与退信处理。
- 会话有效期、账户删除保留期和未成年人边界。
- 认证供应商或自建服务的选择。

这些决策会影响基础设施与合规边界，因此在确认前不把某个第三方 SDK 写死到前端。
