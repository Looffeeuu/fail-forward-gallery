# V0.2 认证契约

## 身份边界

- `account_id` 是服务端私有标识，不得进入公开故事、评论或 Follow-up 响应。
- 公开内容只返回匿名作者类型，例如 `anonymous-member`。
- 中国区手机号用于后台账户验证，不作为公开昵称，也不进入全文审核提示词。
- 当前数据库只保存带服务端密钥的手机号指纹，不保存明文手机号。
- 邮箱后续作为可选通知和申诉渠道，不作为中国区主要身份验证方式。
- 管理员界面默认不展示手机号或邮箱；只有具备明确权限和审计记录的操作才能查看必要身份信息。

## 客户端适配器

正式认证实现需要向 `window.FFG_AUTH.configure(adapter)` 提供：

```js
{
  restoreSession(),
  requestPhoneCode(phone),
  verifyPhoneCode({ phone, code }),
  signOut()
}
```

适配器返回的账户对象只应包含客户端授权所需的最少字段。浏览器端不保存长期令牌；正式会话建议由服务端通过 `Secure`、`HttpOnly`、`SameSite` Cookie 管理。

当前 `auth-http-adapter.js` 已实现该契约，接口细节见 [auth-api.yaml](./auth-api.yaml)。前端运行配置只包含公开值，禁止放置邮件服务密钥、数据库凭据或签名密钥。

## 内容归属接口

- `POST /api/v1/stories` 只接受已登录会话；作者账户由服务端 Cookie 会话解析。
- `GET /api/v1/me/stories` 只返回当前账户拥有的故事及审核状态。
- 浏览器即使传入 `accountId` 或其他作者字段也不会改变内容归属。
- 新故事同时创建审核记录，初始状态为 `pending-human-review`；AI 未接入时明确记录为 `not-configured`。
- 当前没有公共“待审核故事”接口，Story Archive 不会读取未通过人工审核的投稿。

## 最低安全要求

- 短信验证码有短有效期、单次使用、尝试次数和发送频率限制。
- 请求验证码时始终返回模糊结果，避免泄露手机号是否已经注册。
- 登录、退出、验证码失败和敏感账户操作写入安全审计日志。
- 修改手机号、导出数据和删除账户前需要重新验证。
- 投稿、评论和 Follow-up 的所有权由服务端根据会话确定，客户端传入的账户 ID 不可信。
- 不在日志、分析事件或错误追踪中记录验证码、完整手机号、完整邮箱和故事正文。

## 待确认决策

- 中国用户的部署地区、跨境数据与隐私合规方案。
- 中国大陆短信签名、模板和服务商资质。
- 可选通知邮箱的服务商、发件域名与退信处理。
- 会话有效期、账户删除保留期和未成年人边界。
- 认证供应商或自建服务的选择。

这些决策会影响基础设施与合规边界，因此在确认前不把某个第三方 SDK 写死到前端。
