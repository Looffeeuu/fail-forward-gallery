# V0.1 产品需求

## 1. 产品定位

Fail Forward Gallery 是以失败经历为主题的匿名表达与同伴支持平台。它为青年提供倾诉、被看见和获得边界清晰的回应的空间。

平台是同伴支持与教育项目，不是医疗、诊断、治疗或紧急救援服务，也不承诺用户一定会“走出失败”。没有变化、仍然困难或不愿透露近况，都属于有效表达。

## 2. 初期用户

- 主要面向中国境内的大学生、研究生和初入社会的青年。
- 默认界面语言为简体中文。
- 同时提供完整英文界面，服务交换生、留学生和跨文化使用场景。
- 用户生成内容保留原始语言；平台不会在未经同意时自动改写或翻译。

## 3. 角色与权限

### 访客

- 阅读已公开的故事、评论、Follow-up 和 Advice Hub。
- 使用主题、标签、回应偏好、搜索和榜单浏览内容。
- 不得看到作者账户、邮箱或内部审核信息。

### 登录用户

- 公开身份始终显示为匿名用户。
- 创建故事和评论。
- 查看自己内容的审核状态。
- 为自己的故事添加 Follow-up。
- 撤回待审核内容，或申请删除已公开内容。
- 对 AI 拒绝或人工拒绝结果提交一次结构化申诉。

### 审核员

- 查看待审核正文、AI 分类、命中规则和必要上下文。
- 批准、拒绝、要求修改或置于安全保留状态。
- 不应在日常审核列表中看到不必要的账户身份信息。
- 所有操作必须写入不可由普通用户修改的审核记录。

### 管理员

- 管理审核员权限、平台规则版本、标签和 Advice Hub 内容。
- 处理申诉、内容举报和删除请求。
- 查看安全与运营指标，但不得导出无关个人数据。

## 4. 登录与公开匿名

- 投稿和评论均要求登录，以支持内容归属、通知、申诉、撤回和滥用治理。
- 认证服务保存邮箱验证关系，业务数据库主要使用不可公开的用户 UUID。
- 公开 API 不返回邮箱、认证提供方标识、设备信息或稳定的跨故事公开昵称。
- 故事详情只显示“匿名作者”；Follow-up 显示“来自原匿名作者的更新”。
- 系统不得向其他用户提供通过多个故事追踪同一作者的标识。

## 5. 投稿前提示

进入投稿流程时显示“动笔之前”弹窗，至少包括：

- 平台不是临床或紧急救援服务。
- 不要填写姓名、电话、邮箱、学号、详细地址和可识别第三方的信息。
- 内容公开前经过 AI 风险分类和人工审核。
- 涉及紧急危险的内容不会直接公开。
- 作者可以选择回应边界，并可申请撤回或删除。

用户必须勾选“我已阅读并知晓”才能继续。系统记录同意时间和规则版本；规则发生实质变化后需要重新确认。

## 6. 故事、评论与 Follow-up

### 故事

- 包含标题、正文、主题板块、标签和回应偏好。
- 默认匿名公开，但只有人工批准后才真正公开。
- 作者可以在个人中心查看状态。

### 评论

- 必须遵守作者选择的回应偏好。
- 与故事使用同一审核状态机。
- “不接收评论”的故事不显示评论输入区域，也不接受评论 API 请求。

### Follow-up

- 仅原故事作者可创建。
- 支持“仍然很困难”“没有明显变化”“正在尝试一些小行动”“比之前好一些”“不想回答”。
- 不要求积极结局。
- 匿名公开的 Follow-up 需要人工批准；仅自己可见的更新仍进行基础安全检查，但不进入公开内容。

## 7. 标签

- 官方标签具有稳定 ID、中文标签、英文标签和适用板块。
- 用户可以提出自定义标签；自定义文本先作为建议记录，不直接成为公开筛选项。
- 自定义标签经过规范化、同义词检查和内容审核。
- 至少被 3 位不同用户用于已批准内容后，进入“待晋升”状态。
- 只有管理员可以将其晋升为官方推荐标签。

## 8. 榜单

榜单面向内容，不对用户或“失败程度”进行排名。建议名称：

- 正在受到关注：结合近期去重浏览、已批准评论和时间衰减。
- 阅读最多：按 24 小时或 7 天去重浏览统计。
- 讨论最多：只统计已批准评论。
- 审核团队推荐：由授权人员维护并记录推荐理由。

安全保留、待审核、已撤回、已删除和选择不公开的内容不得进入榜单。“不接收评论”的故事不得进入讨论最多榜单。

## 9. Advice Hub

- 使用卡片展示标题、摘要、主题、标签和预计阅读时间。
- 展开或进入详情后显示完整建议。
- 每篇正式内容记录来源、编辑负责人、发布日期和最后复核日期。
- 避免诊断、治疗和疗效承诺；高风险主题需要专业复核。

## 10. 非功能要求

- 移动端优先，兼顾桌面端。
- 键盘操作、焦点管理、语义结构和文字对比度达到基础 WCAG AA 目标。
- 中英文切换不刷新页面、不清空表单、不改变筛选状态。
- 敏感操作有明确反馈，不使用羞辱性或强制积极的措辞。
- 正式接口失败时不能让用户误以为内容已成功提交或公开。
