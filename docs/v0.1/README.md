# Fail Forward Gallery V0.1 基础规范

V0.1 的目标不是立即上线完整社区，而是冻结正式产品的核心边界，使登录、投稿、评论、Follow-up、审核、标签和榜单可以在同一套规则下逐步实现。

## 本版本完成内容

- 明确公开匿名与系统内账户身份的分离方式。
- 明确故事、评论和 Follow-up 的统一审核状态机。
- 明确 AI 只负责风险分类和拦截，只有人工可以批准公开。
- 明确邮件只发送通知，不作为正文存储和审核数据库。
- 定义正式数据库的核心实体、权限边界和审计要求。
- 定义前端、API、数据库、审核服务、邮件服务和管理后台的边界。
- 建立统一界面语言状态：首次访问默认中文，同时提供英文界面。

## 暂不属于 V0.1 的实现

- 真实登录和账户找回。
- 真实数据库与跨用户数据同步。
- 真实 AI 内容审核接口。
- 管理员审核后台。
- 正式邮件发送。
- 实时榜单与防刷统计。
- 正式危机资源目录。

现有浏览器本地存储、模拟审核和演示控制仍是过渡实现。任何页面中出现的原型能力都不能被视为已经上线的正式服务。

## 已确认的产品决策

1. 投稿者和评论者都需要登录，但公开页面始终匿名。
2. 账户身份仅用于内容归属、Follow-up、状态通知、撤回和申诉。
3. 用户邮箱不进入公开内容表，也不显示给审核员以外的无关角色。
4. 邮箱用于身份验证和状态通知，不传输完整故事或评论正文。
5. AI 可以拒绝明确违规内容，但用户可以申请人工复核。
6. 只有人工审核员可以把故事、评论或 Follow-up 批准为公开状态。
7. 涉及自伤、自杀或紧急危险的内容不直接公开，也不自动改写为积极内容。
8. 界面默认中文；用户切换到英文后，仅在当前浏览器保存语言偏好。
9. 用户生成内容保留作者原语言，不进行默认机器翻译。

## V0.1 完成标准

- 产品、安全、数据和架构规范之间不存在状态或权限冲突。
- 默认中文和英文切换不重置筛选、投稿标签或故事数据。
- HTML 文档语言属性随界面语言更新。
- 所有新后端接口都可以映射到本文档规定的状态和权限。
- 在真实后端完成前，不把当前静态页面描述为已经具备正式审核、邮件或共享数据能力。
